# 用户要求与边界

更新日期：2026-11-14，时区 Asia/Hong_Kong。以下来自用户在本项目对话中的明确要求；变更时记录新决定及原因。

## 设备与目标

- 车型：银河 E5；车机处理器：龙鹰一号。
- 优先降低运行时内存和 CPU 占用，改善录像流畅度，同时保留可靠录像与转向补盲。
- 原车行车记录仪是独立硬件，不能用它的流畅度直接推断车机 SoC 的性能。
- 用户目前不方便持续实车测试。优先完成可离线验证的工作，不把尚未实测的性能估算写成结论。

## 必须保留

| 功能 | 已确认行为 |
| --- | --- |
| 日常录像 | 左、右、后三路；前摄不参与日常录制 |
| 飞书远程控制 | 保留远程拍照、录像和上传；远程录像需要前、后、左、右四路，前摄必须能按需启用 |
| 录制切换 | 日常录像与远程任务正确交接，完成后恢复原有日常状态，防止释放/重开竞态 |
| 主界面实时预览 | 手动开关，默认关闭，保存偏好；完全退到后台时停用主预览 |
| 转向补盲 | 转向触发与相应画面输出不能被节流/释放策略误关 |
| HUD | 保留 Android 副屏/EVCC 虚拟显示和 Wi-Fi/ESP32 两种输出路径；用户尚未确认实际使用哪一种，不可再次笼统移除“副屏”或“网络推流” |
| 基础运行保障 | 必要的后台录像、保活、自启动、存储管理和录像清理 |

## 可选录像车辆状态水印（2026-11-14）

- 用户要求增加刹车、车速、左右转向灯状态，默认关闭。
- 关闭或停止录像时不保留此功能专用的信号订阅、图片/纹理或叠加绘制；补盲已拥有的连接仍由补盲管理。不能承诺字节数或分支判断的绝对零开销。
- 开启时多路录像共享一份信号源，优先复用补盲现有 VHAL 连接；不为水印重建摄像头、增加摄像头流或额外视频编码器。
- 没有有效信号必须显示未知。刹车读取踏板信号，不用停车制动、能量回收或减速推测替代。当前标准踏板属性在 E5 是否提供仍需实车确认。
- 水印加入当前 Codec 录像路径，日常三路/远程四路及 HUD 能力保持；本项不等于录像卡顿修复。

## 录像架构对照实验（2026-11-14）

- 用户要求先整改当前卡顿问题，再交付 EVCam 原架构与 Smartcam 思路的两个 APK。
- A 保留日常三路独立文件；B 日常三路合成单视频，飞书四路继续独立文件。B 是明确标识的实验变体，不改变正式版默认需求。
- 两版共用整改、相同包名与签名，顺序覆盖安装以保留配置；不新增两套并行常驻摄像头任务。B 可能降低合成尺寸，须披露实际分辨率和清晰度代价。
- 实现与试录方法见 [A/B 测试说明](RECORDING_AB_TEST.md)，不能将离线验证当成已解决实车卡顿。

## 已授权精简

- 不需要鱼眼矫正、预览矫正及图像调节。
- 停用与本次用途无关的钉钉、Telegram、心跳图片、远程监管/Longview、车门联动、自定义按键、模拟信号等运行时入口/任务。
- “停用”不等于所有旧源码和依赖都从 APK 中物理删除；后续删依赖必须检查共享代码与 HUD/飞书链路。
- 两个个人宣传二维码、联系方式和打赏入口不要。保留功能所需的二维码传输、必要使用提示及 GPL 许可证。

## 界面

- 用户屏幕为 2560×1600，侧边选项太小；放大侧栏整块触控区域、文字与图标，并按可用空间适配，六个入口始终可达。同步到录像 A/B 两版，不依靠全局字体强制缩放。

- 简约现代、统一导航和二级返回逻辑、控件尺寸、间距和字号；使用系统 sans-serif，不引入大型字体包。
- 支持深色/浅色并保存偏好，默认深色。使用原生资源；不增加常驻主题轮询或双份页面。
- 录制中或停止录制交接中不因主题切换重建 Activity。布局编辑时保留未保存操作，先完成/取消编辑再应用主题。
- 录制预览默认排布：左摄在左边，右摄在右边；中间上方前摄、下方后摄。
- 编辑模式支持拖动画面位置、右下角调整大小、预设排版、恢复默认、保存和取消，按比例保存位置/大小/叠放顺序。
- 编辑布局复用现有四个 TextureView，不为编辑创建新的摄像头流、编码器或帧缓存。不能承诺绝对零开销。
