# 进度同步强制规范

更新：2026-11-14 18:50:48 +08:00（Asia/Hong_Kong）。适用于本项目所有 AI 和任务。

根目录 `AGENTS.md` 是唯一规范入口，细则集中维护在已引用文档。禁止AI自行创建平行规则、子目录AGENTS或私有规则/Skill覆盖项目要求；确需新增规范文件必须有用户明确要求。已有工具入口只转引统一规范。任务进度/证据文件可按既定结构创建，不得夹带另一套治理规则。

这是项目执行要求，不是对任何外部AI的技术强制保证；接管前须确认能读取最新文件。自动检查可拦漏记、超长等机械错误，不能证明AI理解规则或实车功能正确。

## 必须执行

1. 开始任务先读 `AGENTS.md`、`STATUS.md`、`REQUIREMENTS.md`、`COLLABORATION.md`，核对 Git、任务登记和本任务相关的坑。
2. 每次有效改动或重要发现后，及时更新本任务进度，不能等聊天结束后凭记忆补写。长任务在阶段切换前同步一次。
3. **每次执行结束都必须核对并更新任务文档；未同步文档，不得宣告完成、交付或移交。** 只读且无新发现时，只覆盖“最后核对时间/结论”，不追加空日志。
4. 提交代码时，同一提交应包含相应任务进度；验证/应用发布在提交之后完成的，用后续文档提交补齐结果。应用源码提交与文档提交分清。文档自身常规提交/推送以Git为准，不为写回自身哈希或状态循环提交；同步失败等重要异常仍需记录。

有效改动包括源码、配置、构建/发布、文件位置、协作规则。重要信息包括用户要求/反馈、结论变化、失败、踩坑、回退、限制、阻塞与待办；推翻旧结论也必须记录。普通搜索输出、重复确认、无变化轮询不逐条入账。

## 记什么、写哪里

| 文件 | 职责 | 限制 |
| --- | --- | --- |
| `STATUS.md` | 当前版本/源码/验证、当前结论、待办、最近更新 | 最多80行、6000字符；最近更新最多5条 |
| `tasks/<task-id>.md` | 本任务范围、最新结果、证据、未解决项 | 同一任务复用；最多80行、6000字符；最近记录最多5条 |
| `PITFALLS.md` | 可复用的坑：触发条件、后果、正确做法、证据 | 最多20条当前有效记录；按ID更新，不重复追加 |
| `archive/YYYY-MM/` | 超出限额的历史、已结束阶段、旧状态快照 | 按需读取；归档保留原事实和证据链接 |

长期需求更新 `REQUIREMENTS.md`，开发方式更新 `DEVELOPMENT.md`，协作变化更新 `COLLABORATION.md`。进度只留一句结论和链接，不复制整份需求、分析、长日志或全部哈希。

## 时间戳和最小记录

统一使用 `YYYY-MM-DD HH:mm:ss +08:00`，时区 `Asia/Hong_Kong`。写实际发生/核对时间；历史只有日期时标注“时刻未记录”，不得猜测补造。

任务文档至少包含：

```text
最后更新：<完整时间戳>
最后核对：<完整时间戳>
任务/执行者：<任务ID / AI或对话标识>
分支/工作树：<分支 / 绝对路径>
状态：执行中 / 等待实测 / 等待信息 / 未集成 / 已完成
当前结论：<一句话>
最近记录：
- <时间戳> | <改动/发现/踩坑/验证/发布> | <结果> | <提交或证据链接>
下一步：<明确动作或无>
```

每条记录只写“发生什么、结果、证据/下一步”，一般不超过140字。相同事项覆盖旧摘要；长细节放专题文档。踩坑在 `PITFALLS.md` 记录，进度引用其ID即可。

## 多 AI 同步

- 并行修改使用独立工作树/分支，各自只更新自己的任务文档；总览由用户指定的协调/集成对话维护，避免抢写。
- 阶段交接登记任务、负责范围、工作树绝对路径、状态、更新时间和最新提交。工作树文档不会自动出现在主目录；通过用户或已授权协作通道交接摘要，协调者再更新总览。
- 未集成结果明确标“未集成”，不能当成主项目或已发布状态。没有协调者时，也必须更新自己的任务文档并指出总览待同步，不能省略记录。
- 每个 AI 都应重新读取实际文件与 Git，不依靠其他对话的口头承诺；发生冲突先保留双方事实再协调，不覆盖别人的记录。

## 收尾核对

- 当前结论与 Git/实际文件一致；记录了时间、结果、证据和未解决项。
- 区分“已实现、构建通过、模拟器通过、实车通过”；推断标注为推断，不把候选修正写成已确认根因。
- 新坑/用户重要反馈已入文档；旧结论失效已更正；没有重复流水账。
- 超限先归档、保留索引，再压缩当前文档；不得为缩短文档删除唯一证据。归档不是默认必读内容。
- 文档检查完成后再交付；未执行的检查如实写“未执行”。纯文档工作不改 APK 版本、不重建 APK。
