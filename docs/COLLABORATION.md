# 多 AI 协作规范

更新：2026-11-14 18:50:48 +08:00。[进度同步强制规范](PROGRESS_RULES.md)适用于所有任务；本规范不自动创建对话或代理。

规范只通过根目录 `AGENTS.md` 及其既有引用维护，禁止各AI私建另一套规则。Claude/Cursor兼容入口不复制细则；发现旧副本或冲突先记录并集中修正。

## 开始与分工

1. 读入口、需求、当前进度、相关坑；执行 `git status --short`、`git branch --show-current`、`git log -5 --oneline`。
2. 读主项目 `E:\GPT\EVCam\work\ACTIVE_TASKS.md`，确认任务ID、执行者、负责文件、依赖和协调/集成人；范围冲突先协调。
3. 并行改代码必须使用不同工作树与`codex/`分支。只读审查可共享读取；串行复用主目录前确认没有其他AI写入。

独立工作树开工/交接同时核对主项目 `E:\GPT\EVCam` 的最新规范和总览；新建基线应包含这些规范，既有工作树不能只读旧副本。

```powershell
git -C E:\GPT\EVCam worktree add -b codex/task-name E:\GPT\EVCam-worktrees\task-name codex/e5-recording-startup-fix
```

命令是示例，不表示已创建工作树；基线替换为当前进度确认的分支/提交。不要共享 `app/build` 输出目录。

## 记录与同步

- 各任务复用 `docs/tasks/<task-id>.md`；每次有效改动/重要发现及时更新，每次执行结束核对时间、结果、证据、待办。时间用 `YYYY-MM-DD HH:mm:ss +08:00`。
- 总览 `docs/STATUS.md` 由协调/集成对话维护，各任务不要抢写。阶段交接提供短摘要、任务文档/工作树绝对路径、更新时间和提交；未集成必须标明。
- 不同工作树/对话不会自动同步文件。更新后通过用户或已授权通道交接；协调者把结论整合进总览。没有协调者也必须记自己的任务进度，并标明总览待同步。
- `work/ACTIVE_TASKS.md` 是本机登记表，只由指定协调者写；字段：任务ID、执行者、范围、工作树/分支、依赖、状态、最后更新时间、最新提交/集成状态。
- `work/outputs`不随Git或工作树复制。同机共享工具/证据按绝对路径读，构建参数见 `DEVELOPMENT.md`。

## 集成与完成

- 代码提交包含任务进度；后续测试/发布用文档提交补结果。未更新文档不得宣告完成，详细格式/限长见 `PROGRESS_RULES.md`。
- 集成人复核/合并、解决冲突、更新总览与必要的需求/架构/坑记录，运行与合并范围相称的检查；明确哪些结果只在分支或模拟器验证。
- 发布由集成人统一做，核对版本、源码提交、APK哈希和未测事项；不要多AI生成同名版本或覆盖交付。
- 不擅自reset/clean、覆盖他人未提交修改、强推或大范围格式化。文档冲突保留双方事实再协调，不删除唯一证据。
- 聊天不是进度文档；不假定其他对话已经知道。收尾只留当前状态、短记录和证据链接，历史按月归档。
