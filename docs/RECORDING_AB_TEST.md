# E5 录像整改 A/B 对比测试

2026-11-14，当前 E5 启动兼容修正版 `1.6.6-test-11141103`，分支 `codex/e5-recording-startup-fix`。先前 `11140958` A/B 用户反馈均不能开始录像，应改测修正版。具体修正和关闭预览旧片分析见 [E5 启动修正](E5_STARTUP_FIX_20261114.md)。

## 两个 APK 的区别

| 项目 | A：独立录像 | B：合成录像 |
| --- | --- | --- |
| 方法 | 保留 EVCam 现有 GL/MediaCodec 三路独立编码架构，加入共用整改 | 参考 Smartcam 的多路 GL 合成、单编码器思路自行实现 |
| 日常输出 | 左、后、右各一个 MP4 | E5 原生画布 2×2：左上左、右上后、左下右，第四格黑，一个 `_combined.mp4` |
| 编码 | 优先可实际配置的硬件 HEVC，兼容选项可用 H.264 | 硬件 H.264；Release 不静默改用软件合成编码 |
| 尺寸 | 保留各路输入尺寸 | 默认画布 1280×800，每格约 640×400；硬件配置失败再尝试 960×600、640×400 |
| 飞书四路 | 四路独立文件 | 四路独立文件，保留既有远程上传协议 |
| 车辆状态水印 | 保留，默认关闭 | 保留，默认关闭 |
| 应用包名/签名 | 两版相同，顺序覆盖安装 | 两版相同，顺序覆盖安装 |

A 不是未经整改的旧 APK。它保留原架构，与 B 共用写盘、分段和 FPS 整改。Smartcam 的原版 APK 本身未经实车测试，本次没有复制其源码或素材，也没有宣称行为逐字节相同。

B 使用各相机最新可用帧，合成时刻不代表三路曝光严格同步；单路超过 1.5 秒未更新时对应格显示黑色，避免用另一格或旧画面伪装实时。B 少用编码器，但增加合成 GL 通路与中间缓冲，不能预先保证内存更低或速度更快。降低尺寸会损失每格细节，必须和帧率一同评估。最终编码器、合成尺寸及回退记录在应用日志。

## 两版共用整改

- 将 codec 输出提取移到专用 drain 线程，将压缩帧复制后尽快释放 codec 输出缓冲；磁盘封装由独立 writer 完成，避免逐帧 GL 回调等待写盘。
- 每编码器采用 4 MiB / 64 样本的队列与保留缓冲预算。超限或写入失败明确报错；不使用无限队列，也不把丢帧悄悄当成成功。
- MP4 先写 `.mp4.pending`，尾帧、封装完成后改为正式 `.mp4`。图库与上传不会把未完成文件当成成功录像。异常或断电遗留的 pending 不保证可修复，应保留排查，需手动关注空间。
- 分段在关键帧换 MP4，保留相机、EGL 输入和同一个编码器；不再每段停止、释放和重建整个编码链路。分段点允许等待关键帧，不保证严格到毫秒。
- 停止先暂停各路提交，再排空 EOS 与写盘尾部；完成回调在收尾之后触发。排队的健康恢复任务不能复活已停止的录像。
- E5 保留旧版 HAL 默认 FPS，其他车型只选择相机报告支持的范围；不兼容组合回 HAL 默认并记录。校验编码器能力并实际 configure，E5 对尺寸/帧率广告采用兼容处理；HEVC/H.264 分别计算码率。
- 添加低频的相机源帧、GL、编码输出和写盘耗时统计，帮助下一轮区分源帧不足与应用阻塞。HUD 与补盲输出需求继续独立保留。

## 安装与试录

1. 先停止现有录像，等停止完成，再安装 A；无需卸载。桌面名为“EVCam A 独立录像”。两版同包名，不能同时安装运行；覆盖安装保留已有偏好和录像。
2. 日常三路、内置存储、预览开启，复现用户本次条件。两版保持同样的分段、画质、时间水印、HUD、补盲和前后台状态。首轮关闭车辆状态水印，单独比较录制架构。
3. 建议每版录至少 2–3 分钟，并跨过一次分段；使用有持续运动的同一路线/场景。留意预览卡顿、停止耗时、每段能否播放、分段前后是否漏画面以及清晰度。
4. 停止后保存原始 MP4 和应用日志，记下 A/B、实际时间、预览/HUD 状态。A 保存三路原片；B 保存合成原片。不要先用聊天软件转码。
5. 顺序覆盖安装 B，桌面名为“EVCam B 合成录像”，重复同样条件。建议再测一次 A，降低温度和场景差异带来的误判。
6. 基础录制比较完成后再分别检查飞书四路/上传/日常恢复、转向补盲、真实 HUD；最后才开启车辆状态水印做单独开关对照。E5 刹车踏板字段是否有数据仍待实车确认，未知不得理解为未刹车。

已有偏好仍会保留，包括曾经打开的水印设置。“默认关闭”指首次未设置时，安装不会强制清除用户选择。

## 离线验证与局限

最终结果和交付哈希见 `docs/STATUS.md` 与 `outputs/EVCam-Recording-AB-notes.md`。JVM 测试覆盖有界积压、样本独立拷贝、写盘失败、停止尾部、FPS 选择、停止恢复竞态、HEVC 码率及合成文件识别。

Android 11 x86 模拟器使用实际 SurfaceTexture → GL → MediaCodec → MP4 流程，输入红/绿/蓝三路不同帧，跨多次关键帧分段，检查首帧关键帧、每段 PTS 从零递增、停止返回后的完整文件和合成颜色。另做车辆状态水印真实 GPU 绘制与设置/合成回放检查。模拟器允许软件 H.264，使用低分辨率合成输入，只能确认流程正确，不能证明 E5 硬件负载、长期稳定性或卡顿已消失。

没有物理 E5 设备，尚未完成实车帧率/CPU/PSS/温度对照、真实 Camera2 多路组合、VHAL、HUD、飞书端到端及长时间存储压力测试。
